# Что делает

Отвечает на вопрос менеджера по корпоративной вики, которая живёт на HTTP. Перед поиском всегда читает `wiki-index.md` в корне репозитория, по метаданным выбирает 2–3 релевантных документа и открывает только их.

# Стратегия поиска

1. **Сначала читаю `wiki-index.md`** — там перечислены все документы вики с датами обновления, авторами, разделами. Если индекс пустой или отсутствует — предупреждаю и запускаю `/wiki-index`.
2. **Фильтрую по метаданным** — выбираю документы по ключевым словам темы, приоритет по `updated` (более свежая дата впереди).
3. **Если на тему есть несколько файлов** — выбираю по дате. Если даты близкие или есть прямое противоречие — открываю ВСЕ версии.
4. **Читаю memo/sync/postmortem с приоритетом.** Свежие решения часто оседают в `memo-*`, `sync-*`, `postmortem-*`, а не в каноничных SOP.
5. **Не доверяю полю `status: актуально`.** Статус может стоять на устаревшем файле. Верю `updated`.

# Формат ответа

- **Короткий ответ** одной фразой (сроки, суммы, контакт).
- **Источник**: URL документа в вики (например, `https://host/wiki/finance/process-refund.md`).
- **Если есть противоречие**: список всех версий с датами и пометкой, какая выбрана и почему.

Пример:
```
Ответ: 14 календарных дней.
Источник: finance/process-refund.md (2025-01-20, А. Журавлёва).
Другие версии:
- finance/process-refund-short.md (2023-06-01) — 7 рабочих дней, устарело
- general/memo-2025-01-refund-review.md (2025-01-22) — подтверждает 14 дней
Контакт: support@school.ru.
```
